Contexte & objectif

Les liaisons par ferry constituent souvent le seul lien entre les îles et le continent, mais leur fréquence est bien souvent dictée par l’importance touristique au détriment des besoins réels des habitants. Ce projet propose l’Indicateur de Cohérence de Desserte Maritime (ICDM), un outil reproductible destiné aux chargés de mission mobilité.

IFIndice de fréquence (GTFS) – offre réelle de traversées
IIPIndice d’importance (population + trafic AIS) – poids réel du port

Le croisement des deux indices identifie les ports sous-desservis (forte importance / faible fréquence) ou sur-desservis (faible importance / offre élevée), orientant les décisions d’aménagement maritime.

Données mobilisées

GTFS (Corsica & Brittany Ferries)

Stops, stop_times, trips, routes. Période janv.-déc. 2026. Sources : transport.data.gouv.fr.

Population IGN

Admin Express – communes littorales pour pondérer l’importance démographique.

AIS – Géolittoral (CEREMA)

Trafic par type : pêche, passagers, cargo, tankers, yachts. Intensité normalisée.

Ports SHOM & communes littorales

Typologie d’activité portuaire + filtrage des communes ayant un accès maritime.

Méthodologie : chaîne QGIS (Modeleur graphique)

Étape 1 – Création couches points depuis GTFS

Conversion stops.csv en couche ponctuelle (WGS84 → Lambert93).

Étape 2 – Indice de fréquence (IF)

Jointures stop_times → trips → routes, comptage des passages par port, normalisation [0,1].

Étape 3 – Indice de population (IP)

Filtrage communes littorales, extraction centroïdes, jointure avec Admin Express, normalisation identique.

Étape 4 – Intégration AIS (5 flux)

Jointure spatiale AIS/ports SHOM, remplacement NULL par 0, pondération conditionnelle via CASE WHEN (activité portuaire).

Étape 5 – Calcul IIP & jointure finale

IIP = intensité_peche + passagers + cargo + tankers + yachts + IP. Jointure par le plus proche avec la couche IF.

Étape 6 – Visualisation

Discretisation, taille = IIP (importance), couleur = IF (fréquence). Dégradé continu.

Modèle entièrement paramétrable, exportable en .model3. Reproductible sur d’autres opérateurs (BreizhGo testé).

Construction des indices

📊
Indice de fréquence (IF)
IF = (nb_passages − min) / (max − min)

Normalisation linéaire. Le port le plus fréquenté (max) obtient 1, le moins fréquenté 0.

Exemple extrait : Quiberon (2029 passages) → IF=1 ; Houat (554) → IF=0.

⚖️
Indice d’importance (IIP)
IIP = IP + Σ(intensités AIS pondérées)

IP = population normalisée [0,1]. Les intensités AIS proviennent de Géolittoral, déjà normalisées. Gestion NULL et typologie d’activité (SHOM).

Pondération AIS (adaptable)
Passagers / Pêche / Cargo / Tankers / Yachts×1 ou ×2
modulable

Exemple : un port sans terminal hydrocarbure voit l’intensité tanker forcée à 0 grâce au CASE WHEN basé sur SHOM.

Résultats : double lecture cartographique

Chaque port est représenté par un cercle dont la taille reflète l’IIP (importance) et la couleur l’IF (fréquence). Palette dégradée (bleu → orange → rouge).

BastiaIIP élevé (forte population + trafic AIS) → taille importante. IF modéré.
QuiberonIF très élevé (liaisons nombreuses) mais IIP moyen → sur-desserte potentielle.

Observation clé : Les ports internationaux (Caen, Cherbourg, Le Havre) disposent d’une fréquence élevée mais leur IIP est souvent sous-estimé par les données AIS limitées à la zone métropolitaine. À l’inverse, certains ports corses (Ajaccio, Porto-Vecchio) montrent un déséquilibre avec une forte importance démographique et touristique mais une offre GTFS moins dense.

Limites identifiées & perspectives

Absence AIS hors métropole

Les ports de Corse, Baléares, Sardaigne ne disposent pas d’intensité AIS, l’IIP se base alors uniquement sur la population → potentiel biais.

Comptage des passages

La table trips ne comptabilise parfois qu’un seul sens par trajet, mais l’indice normalisé compense pour la comparaison inter-portuaire.

Population saisonnière

Intégrer les résidences secondaires (INSEE) améliorerait la prise en compte du tourisme estival, surtout pour la Corse.

Shapes des lignes

L’accès à la table shapes.txt permettrait de calculer l’IF par liaison (plutôt que par port) et de cartographier le réseau réel.

Perspectives : ajout d’une dimension tarifaire (données ouvertes de prix) et analyse diachronique sur plusieurs années pour détecter les évolutions de desserte.
